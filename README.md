## 🌟 1. نظرة عامة على المشروع (Project Overview)

**PharmaCare Desktop** هو تطبيق مكتبي متكامل لإدارة الصيدليات المجتمعية يعمل **أوفلاين بالكامل 100% دون الحاجة لأي اتصال بالإنترنت أو خوادم سحابية**.
تم بناء المشروع بلغة **Java 21** وواجهات **JavaFX** مع محرك قواعد بيانات مضمن **SQLite 3**، ويتميز بالتطبيق الدقيق والصارم لخوارزمية **FEFO (First Expired, First Out)** لسلامة صرف الدواء ومنع بيع أي تشغيلة منتهية الصلاحية نهائياً.

## 🏛️ 2. المعمارية البرمجية وهيكل المشروع (Software Architecture)

تم تقسيم المشروع باتباع أفضل الممارسات الهندسية بنمط **(Layered Architecture)** لضمان فصل المهام (Separation of Concerns):

```text
com.pharmacy/

├── MainApp.java                   # فئة Application لتهيئة JavaFX وقاعدة البيانات
├── database/
│   └── Database.java              # إدارة الاتصال بـ SQLite وإنشاء الجداول الـ 6 والـ Seeding
├── model/                         # كائنات البيانات (Data Entities / POJOs)
│   ├── Medicine.java              # كيان الدواء
│   ├── Supplier.java              # كيان المورد
│   ├── Purchase.java              # فاتورة الشراء الرئيسية
│   ├── PurchaseItem.java          # بنود الشراء والتشغيلات (Batches)
│   ├── Sale.java                  # فاتورة البيع
│   ├── SaleItem.java              # بنود الصرف المرتبطة بالتشغيلة
│   └── CartItem.java              # عنصر سلة المبيعات
├── dao/                           # طبقة الوصول للبيانات (Data Access Objects)
│   ├── MedicineDAO.java           # استعلامات الأدوية والأرصدة المحسوبة ديناميكياً
│   ├── SupplierDAO.java           # إدارة بيانات الموردين وحالة التفعيل
│   ├── PurchaseDAO.java           # تسجيل فواتير الشراء بمعاملات ذرية (Transactions)
│   ├── SalesDAO.java              # تنفيذ خوارزمية FEFO والخصم المحمي
│   └── ReportDAO.java             # مؤشرات الأداء (KPIs) ورادار الصلاحيات
├── service/                       # طبقة منطق الأعمال (Business Logic Layer)
│   ├── InventoryService.java      # فحص التصنيفات الستة وقواعد الأدوية
│   ├── PurchaseService.java       # التحقق من تواريخ الصلاحية المستقبلية
│   └── SalesService.java          # فحص سلة المشتريات والخصم الآلي
└── controller/                    # وحدات التحكم لشاشات JavaFX الست
    ├── MainLayoutController.java  # إدارة القائمة الجانبية والتنقل بين الصفحات
    ├── DashboardController.java   # لوحة المؤشرات، النواقص، ورسم المبيعات البياني
    ├── MedicinesController.java   # كتالوج الأدوية، البحث، الفلاتر، والإضافة والتعديل
    ├── SuppliersController.java   # سجل الموردين وحالة النشاط
    ├── PurchasesController.java   # شاشة تسجيل فواتير التوريد واستعراض السجل
    ├── SalesController.java       # شاشة الكاشير السريعة (POS) والباركود
    └── ReportsController.java     # كشوفات المبيعات والمشتريات وتصدير CSV
```

## 🗄️ 3. تصميم قاعدة البيانات (The 6 Core Tables)

تعتمد قاعدة البيانات على 6 جداول رئيسية وفق المواصفات القياسية:

1. **`medicines`**: بيانات الأصناف الدوائية (الاسم، التصنيف، الباركود، سعر البيع بالقروش، حد إعادة الطلب، حالة التنشيط).
2. **`suppliers`**: بيانات شركات التوزيع والموردين (الاسم، الهاتف، العنوان، حالة التنشيط).
3. **`purchases`**: الترويسة الرئيسية لفاتورة التوريد (المورد، تاريخ الشراء، رقم الفاتورة، الإجمالي).
4. **`purchase_items`**: **(مصدر الحقيقة الأوحد للمخزون)**: كل سطر يمثل تشغيلة معينة (Batch Number)، وتاريخ صلاحيتها، والكمية المستلمة، والكمية المتبقية، وسعر الشراء.
5. **`sales`**: ترويسة فاتورة المبيعات (تاريخ ووقت البيع، إجمالي الفاتورة، طريقة الدفع: CASH أو CARD).
6. **`sale_items`**: تفاصيل الأدوية المصروفة مع ربطها المباشر برقم تشغيلة الشراء `purchase_item_id` وسعر البيع التاريخي وقت العملية.

## 💡 4. دليل المذاكرة والمناقشة الشفوية مع الدكتور (Exam Defense Guide)

هذا القسم تم إعداده خصيصاً لأعضاء الفريق للاستعداد لأي سؤال قد يطرحه الدكتور أثناء مناقشة المشروع:

### س1: ما هو الفرق الجوهري بين خوارزمية FIFO وخوارزمية FEFO؟ ولماذا اخترنا FEFO؟
* **الإجابة**:
  * **FIFO (First In, First Out)**: يبيع البضاعة التي وصلت الصيدلية أولاً بصرف النظر عن تاريخ صلاحيتها، وهذا قد يتسبب في كارثة بالصيدليات إذا وصلت شحنة جديدة بتاريخ صلاحية أقرب من شحنة قديمة.
  * **FEFO (First Expired, First Out)**: يقوم النظام آلياً بترتيب التشغيلات المتاحة لنفس الدواء بحسب **تاريخ الانتهاء الأقرب (`expiry_date ASC`)**، ويصرف منها أولاً، مما يضمن خروج الأدوية الأقرب للانتهاء ومنع هدر الأدوية وحماية صحة المرضى.

### س2: أين يخزن رصيد الدواء (Stock)؟ ولماذا لا يوجد عمود `stock` في جدول `medicines`؟
* **الإجابة**:
  * المخزون **لا يُخزن كقيمة ثابتة في جدول الأدوية** منعاً لتضارب البيانات (Data Redundancy) والوقوع في أخطاء التزامن.
  * جدول `purchase_items` هو **المصدر الأوحد للحقيقة (Single Source of Truth)**.
  * رصيد الدواء الصالح للبيع يُحسب ديناميكياً عبر استعلام:
    ```sql
    SELECT SUM(quantity_remaining) 
    FROM purchase_items 
    WHERE medicine_id = ? AND expiry_date >= date('now') AND quantity_remaining > 0;
    ```
  * أي تشغيلة تاريخها قبل تاريخ اليوم (`expiry_date < date('now')`) تُستبعد برمجياً وتلقائياً ولا تظهر للكاشير.

### س3: كيف حمينا النظام من بيع أدوية غير متوفرة أو حدوث رصيد سالب (Concurrency & Guarded Updates)؟
* **الإجابة**:
  * في ملف `SalesDAO.java`، نقوم بتحديث رصيد التشغيلة بشرط صارم ومحمي:
    ```sql
    UPDATE purchase_items
    SET quantity_remaining = quantity_remaining - ?
    WHERE purchase_item_id = ? 
      AND quantity_remaining >= ? 
      AND expiry_date >= ?;
    ```
  * إذا لم يؤثر التحديث على صف واحد بالضبط (`affectedRows != 1`)، يتم إيقاف العملية وإلغاء المعاملة فوراً (`rollback`)، مما يمنع حدوث أي رصيد سالب نهائياً.

### س4: لماذا تم استخدام المعاملات (Database Transactions) عبر `conn.setAutoCommit(false)`؟
* **الإجابة**:
  * لضمان مبدأ **الذرية (Atomicity)** في قواعد البيانات: إما أن تنجح العملية بالكامل أو تفشل بالكامل.
  * عند تسجيل عملية بيع أو شراء، هناك عمليات مترابطة (إدخال الفاتورة، خصم التشغيلات، وإدخال بنود الصرف). إذا حدث انقطاع في الكهرباء أو خطأ في أحد البنود، يتم تنفيذ `conn.rollback()` فلا تضيع البيانات ولا يحدث خلل في الحسابات.

### س5: لماذا تم تخزين المبالغ النقدية كـ Integer (قروش) في قاعدة البيانات واستخدام `BigDecimal` في الجافا؟
* **الإجابة**:
  * أنواع الأرقام العشرية العادية مثل `double` و `float` تسبب أخطاء تقريب ثنائية مشهورة (Binary Floating-Point Rounding Errors) مثل `0.1 + 0.2 = 0.30000000000000004`، وهو أمر مرفوض تماماً في الأنظمة المحاسبية.
  * لذلك خزنّا النقود كقروش صحيحة (1 جنيه = 100 قرش)، واستخدمنا `BigDecimal` في الجافا لضبط العمليات الحسابية بدقة متناهية.

### س6: كيف يدعم النظام تصدير تقارير Excel باللغة العربية دون أن تظهر الحروف كرموز غريبة؟
* **الإجابة**:
  * عند إنشاء ملف الـ CSV في `ReportsController.java`، نكتب في بداية الملف علامة **UTF-8 Byte Order Mark (`\uFEFF`)**:
    ```java
    writer.write('\uFEFF');
    ```
  * هذه العلامة تجعل برنامج Microsoft Excel يتعرف فوراً وبشكل تلقائي على أن الترميز هو UTF-8، فتظهر الكلمات العربية واضحة ومنسقة تماماً.

## 🚀 5. متطلبات التشغيل وطريقة البدء (How to Run)

### المتطلبات الأساسية:
- نظام تشغيل Windows 10 أو Windows 11.
- تثبيت **Java JDK 21** أو **JDK 17**.
- برنامج **Apache NetBeans** أو أي محرر يدعم Maven.

### التشغيل من داخل NetBeans:
1. افتح Apache NetBeans.
2. اختر **File** ⬅️ **Open Project** واختر مجلد المشروع.
3. اضغط كليك يمين على المشروع ثم **Run** (أو اضغط **F6**).

### التشغيل عبر سطر الأوامر (Command Line):
```bash
mvn javafx:run
```

### التشغيل بنقرة واحدة (One-Click):
قم بالضغط مرتين على ملف **`run.bat`** داخل المجلد الرئيسي وسيقوم ببدء التطبيق فوراً بأقل استهلاك للذاكرة.

## 🔒 6. مكان ملف قاعدة البيانات المضمنة (SQLite Database Path)

يتم إنشاء وتخزين ملف قاعدة البيانات تلقائياً في المسار المحلي الخاص بالمستخدم:
```text
%LOCALAPPDATA%\PharmacyManagementSystem\pharmacy.db
```
وعند أول تشغيل، يقوم النظام تلقائياً بإنشاء الجداول وإدراج بيانات تجريبية (Seeding) لمجموعة من الأدوية والموردين والتشغيلات ليكون البرنامج جاهزاً للعرض أمام لجنة المناقشة مباشرة.
